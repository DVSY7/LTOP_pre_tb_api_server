# PRE LTE 통신 테스트 프로그램

서버와 독립적으로 관리하는 Windows 시연·통신 테스트 도구입니다. 서버 코드는 저장소의 `api_server/`, 서버 의존성은 루트 `requirements.txt`에 있습니다. 이 디렉토리만 별도 PC로 복사해 개발하거나 빌드할 수 있습니다.

## 배포 파일로 실행

`dist/PRE-LTE-Tester.exe`를 실행합니다. Python 설치는 필요하지 않습니다. 다른 PC에는 `dist/PRE-LTE-Tester-Windows.zip`을 전달하고 압축을 풀어 사용하면 됩니다. 모뎀용 Windows USB/COM 드라이버는 해당 PC에 설치되어 있어야 합니다.

실행 파일에는 서버 코드, `.env`, DB 비밀번호가 포함되지 않습니다. 별도의 관리자 권한은 필요하지 않습니다. 서명되지 않은 자체 빌드이므로 Windows에서 게시자를 확인할 수 없다는 안내가 나올 수 있습니다. 다른 운영체제용 실행 파일은 해당 운영체제에서 별도 빌드해야 합니다.

## 화면 사용 순서

기본 창은 최대 1280×760으로 화면 크기에 맞춰 실행됩니다. 1100×668 이상 일반 창과 최대화에서는 전체 페이지 스크롤 없이 주요 UI를 표시하고, 남는 높이를 로그·결과 영역에 배분합니다. 창 너비가 약 1000픽셀보다 작으면 전송 준비와 결과를 위아래로 재배치합니다. 최소 크기는 640×480이며 작은 창에서 높이가 부족할 때만 전체 스크롤바를 표시합니다. COM 연결 영역은 같은 부모 안에 직접 배치하고 좁은 창에서 줄바꿈합니다. 로그와 결과 표 안에서는 해당 영역의 스크롤이 우선합니다.

선택된 탭은 파란색 배경으로 표시하며 선택 전후 크기와 여백은 동일합니다. 제목은 설치된 한글 글꼴의 보통 굵기로 표시합니다.

1. USB 모뎀을 연결합니다. 2초 간격으로 COM 포트를 감지합니다. 후보가 하나면 자동으로 연결을 시도하며, 여러 개라면 사용자가 모뎀 COM 포트를 선택합니다. 같은 포트를 사용하는 다른 프로그램은 종료합니다.
2. 상단에서 **모뎀 응답 → SIM → LTE 망 → 데이터망** 상태를 확인합니다. 준비가 완료되면 **테스트 시작** 버튼이 활성화됩니다. 서버/DB 상태는 실제 전송 후 별도로 표시합니다.
3. **전송 데이터** 탭에서 장비 ID, 배터리, 온도, 방식 전위, 습도를 입력합니다. **통신 설정** 탭은 서버 주소, API 경로, HTTPS 포트, 응답 제한입니다. **고급 AT** 탭에는 읽기 전용 전송 명령 미리보기와 직접 명령 입력이 있습니다.
4. 10/50/100회 또는 1~1000회를 선택합니다. 반복 간격은 0~60초, 응답 제한은 1~300초입니다. 실제 모드에서는 회차마다 같은 입력값을 전송해 DB에 데이터를 저장합니다.
5. 완료 수, 저장 확인율, 처리 시간 그래프와 회차별 결과를 확인합니다. 완료 팝업과 **결과 CSV 저장**으로 결과를 보관합니다. CSV는 Excel 한글 호환 UTF-8 BOM 형식이며 COM 포트, 통신 속도, 서버 주소, API 경로, 서버 포트와 측정값을 별도 열로 저장합니다. 여러 줄의 AT 원문은 CSV에서 제외하며 화면의 **AT 원문** 탭에서 확인할 수 있습니다.

**데모 · 실제 전송 없음**을 선택하면 장비 없이 시연합니다. 모든 결과는 가상 값이며 10회마다 미확인 사례를 표시합니다. 실제 모뎀, 서버, DB에는 요청하지 않습니다. 모드를 바꾸려면 연결을 해제하세요.

## 자동 확인 기준

조회 명령만 전송합니다. PIN 입력, APN 설정, 망 연결 설정을 임의로 변경하지 않습니다.

| 단계 | 확인 명령 | 준비 기준 |
|---|---|---|
| 모뎀 | `AT` | `OK` 응답 |
| SIM | `AT+CPIN?` | `READY` |
| LTE 망 | `AT+CEREG?` | 등록 상태 1 또는 5(로밍) |
| 데이터망 | `AT+CGATT?` | 1 |
| 신호 참고값 | `AT+CSQ` | RSSI 표시, 99는 미확인 |

유휴 상태에서는 상태 조회 완료 후 약 12~14초마다 다시 확인합니다. 테스트 직전에도 재확인하며 테스트 중에는 상태 조회가 전송과 섞이지 않습니다. 조회 중에는 테스트 시작을 잠시 비활성화합니다. USB 제거는 유휴 중 다음 포트 검색에서 감지하고, 전송 중에는 시리얼 오류 또는 응답 제한 시점에 처리합니다. 수동 **연결 해제**는 자동 재접속을 멈추며 **연결 / 다시 확인**으로 재개합니다.

이 명령을 지원하지 않거나 다른 응답 형식을 쓰는 모뎀은 **미확인 / 명령 미지원**으로 표시하고 시작을 허용하지 않습니다. 모뎀 모델의 AT 문서와 원문을 기준으로 `modem_tester/core.py`를 조정해야 합니다. 데이터망 등록은 HTTPS 서버 접속이나 PDP 활성 상태까지 보장하지 않습니다. AT*WHTTP 지원 및 서버/DB 도달 여부는 실제 전송 결과로 확인합니다.

상태 조회 형식 참고: [Quectel LTE-A AT Commands Manual](https://quectel.com/content/uploads/2021/03/Quectel_EM12EG12EG18_AT_Commands_Manual_V1.0.pdf). 실제 사용 모뎀의 호환성 검증은 별도로 필요합니다.

## 측정 결과 해석

- **DB 저장 확인**: JSON에서 `result=OK`, 일치하는 `equip_id`, 양의 정수 `t_no`를 확인한 경우입니다. 기존 API가 DB 커밋 후 반환하는 응답이 근거이며 DB 직접 조회나 컬럼 값 대조는 아닙니다.
- **중복 응답**: 앱 실행 중 확인한 저장 번호는 새 성공으로 세지 않습니다.
- **저장 미확인**: 유효한 저장 응답을 받지 못했습니다. 실제 저장됐지만 응답만 유실됐을 수도 있습니다. 자동 재시도하지 않습니다.
- **저장 확인율**: 완료된 시도 중 저장 응답을 확인한 비율입니다. 데이터 정확도나 LTE 링크 품질 지표는 아닙니다.
- **왕복 처리 시간**: AT 전송 설정부터 응답 또는 제한 시간까지입니다. 사전 상태 점검은 제외하며 평균에는 미확인 시도도 포함합니다. 순수 전송 속도(bps)는 아닙니다.

중지와 창 닫기는 현재 요청의 응답/제한 시간을 기다린 뒤 처리합니다. 이미 저장된 DB 데이터는 삭제하지 않습니다. 서버 초기 기동이 느리면 응답 제한을 늘리세요.

현재 전송 흐름은 `AT*WHTTP=1,...` → `AT*WHTTP=3` 후 JSON 본문이 직접 출력되는 방식입니다. 별도 읽기 명령이 필요한 모뎀은 수집 코드를 조정해야 합니다. API에 요청별 식별자가 없어 같은 장비의 지연 응답을 특정 회차와 완전히 대조할 수는 없습니다.

## 개발 실행 / 빌드

이 폴더에서 다음을 실행합니다. 개발 환경은 Python 3.10 이상과 Tkinter가 필요합니다.

```powershell
python -m venv .build-venv
.\.build-venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.build-venv\Scripts\python.exe app.py
.\.build-venv\Scripts\python.exe -m unittest discover -s tests -v
.\.build-venv\Scripts\python.exe build.py
```

기존 저장소 가상환경은 `..\.venv\Scripts\python.exe app.py`로 실행합니다. 빌드는 [PyInstaller의 onefile/windowed 방식](https://www.pyinstaller.org/en/stable/usage.html)입니다. `dist/`에는 EXE, 사용 안내, SHA256 체크섬, 배포 ZIP이 생성됩니다. `build/`, `dist/`는 Git에서 제외합니다.

기존 EXE가 실행 중이면 덮어쓸 수 없습니다. 실행 창을 닫은 뒤 빌드하거나 `python build.py --output-dir dist/ui-update`로 별도 폴더에 수정본을 생성할 수 있습니다.

빌드 실행 파일 시작 검증(모뎀 접속이나 서버 요청 없음):

```powershell
$process = Start-Process -FilePath .\dist\PRE-LTE-Tester.exe -ArgumentList '--self-check', 'startup-report.json' -WindowStyle Hidden -Wait -PassThru
Get-Content startup-report.json
```

## 파일 구성

```text
lte_tester/
  app.py                   # UI 이벤트, 반복 실행, 결과 저장
  modem_tester/core.py      # 시리얼 통신, 준비/저장 판정
  modem_tester/view.py      # 대시보드 디자인
  tests/                   # 장비 없이 실행하는 회귀 테스트
  requirements.txt         # UI 실행 의존성
  requirements-build.txt   # 빌드 도구
  build.py                 # 단일 EXE와 ZIP 생성
  dist/                    # 로컬 배포 산출물
```

루트의 일회성 `test.py`, `db_test.py`, `run_tester.bat`는 UI/EXE로 대체하여 제거했습니다. `tests/`는 통신 판정, 준비 상태, 데모, CSV, 중지, 연결 해제를 검증하므로 유지합니다.
